# «Когда на права?» — план архитектуры

`client_id` и каталог — `pdd`, домен `pdd.burninghouse.ru`. Название
«Когда на права?» — рабочее, может поменяться (в коде — константа
`SERVICE_NAME` в `server.js` и `assets/app.js`, плюс `index.html`).
Вещество — кальций: `--flame-tip #ff7043`.

Что это: тренажёр билетов ПДД (категория A/B) с планом подготовки, огоньком
за выполненный день и друзьями. Заказчик — Аня. Дальше, возможно, вырастет в
сервис стриков для любых привычек — поэтому стрик с самого начала сделан
**не про билеты**, а про «привычку» (`habit`), у которой ПДД — первая.

---

## Стек

Как у Brain: один `server.js` на `node:http` + `node:sqlite`, без
`node_modules`, статика в `assets/`, `auth-client.js` скопирован из Auth.
Роутинг через History API (`/bilet/7`, `/tema/znaki`), сервер отдаёт на все
валидные пути один `index.html` с подставленными `<title>`/description — ради
поиска «билеты пдд онлайн». Docker + Watchtower, nginx на 443, как у всех.

Порт dev: **8798** (8795 — brain, 8796 — занят e2e, 8797 — movieporter-site).

## База билетов

Источник — [etspring/pdd_russia](https://github.com/etspring/pdd_russia),
категория `A_B`: 40 билетов × 20 вопросов, картинки, темы, пояснения.
Обновляется раз в квартал.

- Импорт скриптом `tools/import.mjs` → `data/questions.json` + `assets/q/*.jpg`.
  В рантайме сеть не нужна, датасет — часть образа.
- Ключ вопроса — **`id` из датасета** (хеш), не «билет+номер»: при квартальном
  обновлении вопросы переставляют и заменяют, а история ответов должна
  остаться привязанной к тому же вопросу.
- **Свои пояснения** — bank/tips-own.json ({ id: { tip, ref } }), всегда
  важнее датасетных; импорт их не трогает. Переписываются по билетам (готовы
  1–2), каждая пачка — с проверкой по картинке и тексту ПДД. SHOW_TIPS=0
  прячет только датасетные. Если вопрос при квартальном обновлении сменил id
  (поменяли формулировку), его своё пояснение перестаёт находиться — такие
  надо пересмотреть по diff импорта.
- Импорт пишет версию датасета (`2026.q3.0`) и diff: какие id ушли, какие
  пришли. Ушедшие вопросы из статистики не удаляем, просто перестаём их
  выдавать и не считаем в «ошибках».
- **Лицензии у датасета нет.** Тексты билетов — официальные материалы ГИБДД,
  а вот `answer_tip` (пояснения) кто-то писал. Для круга друзей — берём как
  есть; до публичного запуска с SEO пояснения нужно переписать или
  договориться с автором. Флаг `SHOW_TIPS` на случай, если понадобится
  быстро выключить.

## Режимы

| Режим | Что | Как засчитывается в план |
|---|---|---|
| Билет | 20 вопросов по порядку, ответ и пояснение сразу | 1 билет |
| Экзамен | как в ГАИ, см. ниже | 1 билет (сдан или нет — неважно, работа сделана) |
| Ошибки | вопросы, где ошибался; уходят после 2 верных подряд | по вопросам |
| Тема | все вопросы одной темы | по вопросам |
| Марафон | все 800 подряд, с сохранением места | по вопросам |

**Экзамен по правилам ГАИ:** 20 случайных вопросов из 4 тематических блоков
по 5, 20 минут. Одна ошибка в блоке — +5 вопросов из того же блока и +5 минут.
Две ошибки в одном блоке, три ошибки всего или ошибка в дополнительных — не
сдал. Пояснения показываем только в конце, как на настоящем экзамене.

Прогресс считается **в вопросах** — единая валюта. «Билет» в плане = 20
вопросов. Так план «2 билета в день» закрывается и двумя билетами, и
экзаменом плюс 20 ошибок, и не нужно отдельно учитывать каждый режим.

## Планы

План — это то, что человек выбирает сам, и огонёк горит, когда выполнена
дневная норма плана.

```
plan = { kind: "daily", target: 40 }            // «2 билета в день»
plan = { kind: "exam_date", date: "2026-11-20" }  // «к дате экзамена»
```

Шаблоны на старте: «Спокойно — 1 билет в день», «Всерьёз — 3 билета»,
«Свой — N билетов», «К дате экзамена».

«К дате экзамена» пересчитывает норму каждый день: сколько вопросов ещё ни
разу не решено верно, плюс все текущие ошибки, делим на оставшиеся дни
(минимум 1 билет). Пропустил день — завтра норма чуть больше; это честнее,
чем фиксированная цифра.

**Смена плана действует с сегодняшнего дня**, прошлое не пересчитываем —
иначе, уменьшив норму, можно «зажечь» прошлые дни задним числом.

## Когда ответ засчитывается

Ответы идут в статистику, огонёк и значки только когда подход закончен:
билет решён целиком, экзамен завершён (в том числе досрочно — «не сдал» тоже
конец), мини-билет, тема или подход к ошибкам пройдены до итога. Брошенный на
середине подход не засчитывается. Решатель (runQuiz) копит ответы и в
showResult отправляет разом — POST /api/answers/batch (гость — в
localStorage); итог билета и экзамена уходит после ответов. Незаконченный
билет по-прежнему запоминается на устройстве (runs), и если его дорешать —
засчитаются все 20 ответов; флаг deferred отличает такие билеты от начатых
до этого правила (их ответы уже засчитаны по одному).

## Без сети

Пропала сеть посреди билета (поезд) — ничего не теряется:

- **Очередь** (progress.js `outbox`) — ответы и итоги билетов/экзаменов
  (`kind: "ticket" | "exam"`) в том порядке, в каком их дали. У каждого `rid`:
  сервер не засчитает повтор (ответы — `answers.rid`, итоги — таблица
  `finishes`), если запрос дошёл, а ответ потерялся. Время — своё (`at`, не
  старше 3 суток): ответ из поезда идёт в свой день.
- **Отправка** — при запуске, по событию `online`, при возврате во вкладку и
  раз в 30 с, пока что-то ждёт. Ответы — пачками в /api/answers/batch, итоги —
  по одному. Если очередь не пуста, новое встаёт за ней, а не обгоняет.
- **На экране сразу**: билет отмечается решённым, огонёк считается
  оптимистично, под итогом — «отправится сам, когда связь появится».
- **Вход не теряется**: auth-client при недоступном auth бросает
  `AuthOfflineError` и токены не стирает (раньше протухший без сети токен
  выглядел как разлогин, и ответы уходили «гостю»).
- **Билеты** — sw.js после установки докачивает все 40 (тексты), картинки
  билета грузятся заранее, как только его открыли.

## Огонёк

Общая для будущих привычек таблица:

```sql
CREATE TABLE activity_days (
  user_id  TEXT NOT NULL,
  habit    TEXT NOT NULL,     -- 'pdd'; потом — любые привычки
  day      TEXT NOT NULL,     -- 'YYYY-MM-DD' в часовом поясе пользователя
  progress INTEGER NOT NULL,  -- сколько сделано (для pdd — вопросов)
  target   INTEGER NOT NULL,  -- норма на этот день, снимок плана
  status   TEXT NOT NULL,     -- 'done' | 'partial' | 'frozen'
  PRIMARY KEY (user_id, habit, day)
);
```

- **День — по местному времени пользователя.** Фронт шлёт IANA-пояс
  (`Europe/Moscow`), он хранится в профиле; «сегодня» считает сервер по нему.
  Иначе у человека во Владивостоке огонёк гаснет в обед.
- **Стрик** — число подряд идущих `done`/`frozen` дней, заканчивающихся
  сегодня или вчера (сегодня ещё не поздно). Вычисляется, не хранится, но
  кешируется в профиле для списка друзей.
- **Заморозки:** одна копится за каждые 7 выполненных дней подряд, в запасе
  максимум 2. Тратятся автоматически: при следующем заходе сервер проходит по
  пропущенным дням и ставит `frozen`, пока есть запас. Кончился — стрик с нуля.
- **Лучший стрик** хранится отдельно — терять его обидно, показывать приятно.

## Друзья

Друзья — из Auth, своего списка нет. Сервер сам зовёт
`GET {AUTH_ISSUER}/api/friends` с Bearer пользователя (как Brain:
`fetchFriendsList`), так что кто кому друг решает Auth, а не клиент.

- **Лента друзей:** имя, огонёк, выполнен ли сегодня план, прогресс по
  билетам (сколько из 40 решено без ошибок), последний экзамен сдал/нет.
  Конкретные ответы и ошибки друзьям не видны.
- **«Подтолкнуть»** — уведомление через Auth, `type: "pdd.nudge"`, не чаще
  раза в день на пару. Текст фиксированный, не свободный: канал Auth — для
  событий, не для переписки.
- **Напоминание себе** — `pdd.streak_risk` вечером, если план сегодня не
  выполнен, а стрик > 0. Время выбирается в настройках, по умолчанию 20:00
  по местному. Нужен простой планировщик в `server.js` (раз в 5 минут).
- **События:** `pdd.exam_passed` друзьям — «Аня сдала экзамен без ошибок»;
  по умолчанию выкл., включается в настройках.

## Гостевой режим

Как у Brain: без входа доступно всё решение билетов, прогресс и огонёк — в
`localStorage`. Вход добавляет друзей, напоминания и синхронизацию между
устройствами. При первом входе гостевая история переносится на сервер:
ответы — как есть, дни — объединением (по дню берём больший `progress`).

## Остальные таблицы

```sql
profiles (user_id PK, tz, plan_json, freezes, best_streak, cur_streak,
          remind_at, share_exams, updated_at)
answers  (user_id, question_id, correct, mode, answered_at)   -- сырой лог
q_state  (user_id, question_id, seen, right_streak, last_wrong_at,
          PRIMARY KEY (user_id, question_id))                 -- для «ошибок»
exams    (id, user_id, started_at, finished_at, passed, errors, questions_json)
nudges   (from_id, to_id, day, PRIMARY KEY (from_id, to_id, day))
```

Ответ всегда пишется на сервере: `POST /api/answers` — сервер сам проверяет,
верный ли ответ, и сам решает, какой сегодня день и закрыт ли план. Клиенту
про стрик не доверяем — иначе в ленте друзей появятся огоньки на 900 дней.

## Оформление: приборная панель

Выбирали в несколько примерок. Каркас Brain выглядел как Brain; первая
«приборка» (почти чёрный фон, всё выделено одним оранжевым с неоновым
свечением, Russo One) — как типовой сгенерированный сайт. Итог:

- **Основа — сине-чёрный цифровой кластер**, приборы — **аналоговые**:
  хромовый ободок, риски, красная зона, красная стрелка. Ночью циферблаты
  чёрные, днём белые на светлой панели.
- **Цвет несут только сигналы:** зелёный «верно», красный «ошибка» и
  отсечка, жёлтый «внимание». Главная кнопка — белая ночью, чёрная днём.
- **Никакого бежевого/кремового и оранжевого в интерфейсе** — это палитра
  Claude и шаблонных «вайбкод»-сайтов. Кальций остался в знаке и свечении фона.
- **Билеты — номерные знаки:** слева результат «18 из 20», в поле региона —
  номер билета, на месте флага — полоска прогресса (зелёная / красная / жёлтая).
- **Шрифты:** Exo 2 (курсив) — цифры, заголовки, кнопки; Golos Text — текст.

Анимации (только transform/opacity, всё выключается при reduced-motion):
- «проверка приборов» при первом заходе за сессию — стрелки до упора и
  обратно к значениям, цифры досчитывают;
- стрелки с лёгким перелётом, лампа «ошибки на повторение» мигает дважды;
- ответ: верный — толчок, неверный — встряска; лампа в ленте загорается;
- новый вопрос въезжает справа, пояснение проявляется.

Огонёк (`streakBlock`/`streakChip`/`celebrateLit` в app.js): контур —
пламя из знака BurningHouse без выреза дома, цвет красный→жёлтый (сигнал,
как лампы, а не акцент интерфейса). Состояния: горит (норма сегодня
выполнена, мерцает, изредка искры), тлеет (серия жива — уголёк дышит,
подсказка «ещё N вопросов»), погас (пунктирный контур). На приборке —
серия, рекорд и «бак» нормы сегментами; в шапке билета — маленький огонёк.
В момент, когда ответ закрывает норму, — карточка: пламя разгорается из
уголька, искры, счётчик дней перещёлкивается, как барабан одометра.

Фон — своя ночная трасса вместо общего bh-backdrop, минималистичная:
ровное холодное небо, тусклое зарево на горизонте, дорога в перспективе с
едва заметной прерывистой разметкой (днём — светлое небо, серая дорога).
Первый вариант со звёздами, фонарями и быстрой разметкой оказался
навязчивым — фон не должен тянуть внимание от вопроса. Скорость — от
огонька и медленная: погас — стоим, тлеет — еле ползём, горит — плавный ход.

На дороге — машина пользователя: плоский векторный синий седан, вид сзади и
чуть сверху, правая полоса. Фар нет: на этом масштабе свет выглядел больше
самой машины. Примерки: вид
строго сзади, «гоночная камера» сверху и честная 3D-проекция седана той же
перспективой, что и дорога, — всё отвергнуто в пользу простой иллюстрации
(«не нужно 3д»). Машина под контентом: между фоном и карточками, видна там, где контента нет. Реакции (carReact в app.js): верно — разгон (машина приседает и уходит
вперёд, дорога плавно ускоряется в 5 раз и возвращается), ошибка — стоп-
сигналы (свечение только у фонарей) и занос с затухающей раскачкой, дорога
резко замедляется; огонёк зажёгся — два подскока. Скорость дороги меняется
через playbackRate её CSS-анимации (Web Animations API) — без скачков. Пока
дорога едет — лёгкое покачивание; реакции его перекрывают (правило
покачивания исключает .ok/.bad/.lit — иначе оно специфичнее и глушило их).

Этап 2 сделан так: логика — lib/store.js (проверки — test/store.test.mjs),
огонёк и заморозки воспроизводятся по истории дней, потраченная заморозка
записывается днём со status='frozen'. Ответы без сети — очередь в
localStorage с rid и временем ответа. Гость хранит свой план локально; его
огонёк считается упрощённо (норма текущего плана на все дни, без заморозок).

Было до этапа 2 (осталось как гостевой вариант): `streak()` в progress.js считает по
`days` из localStorage с фиксированной нормой 20 вопросов (`DAILY_TARGET`),
без заморозок. На этапе 2 норма придёт из плана, а считать будет сервер.

## Первая версия — порядок работ

1. ✅ Импорт датасета, режим «Билет», гостевой прогресс — уже можно дать Ане.
2. ✅ Вход через Auth, серверный лог ответов, план и огонёк, заморозки.
3. ✅ Экзамен по правилам ГАИ, ошибки, темы.

   Сделано так: один «решатель» (runQuiz в app.js) на все режимы — билет,
   экзамен, ошибки, тема отличаются настройками, а не копиями вёрстки.
   Экзамен (/ekzamen): случайный билет, правильность не показывается до
   конца (и машина не реагирует — не подсказывает), доп. вопросы после
   основных 20 из того же блока другого билета, +5 минут на блок, досрочный
   «не сдал»; итог пересчитывает сервер (examVerdict, таблица exams).
   Ошибки (/oshibki): вопрос уходит после 2 верных подряд — то же правило на
   сервере и у гостя; подход до 20 вопросов. Темы (/temy, /tema/N): прогресс
   по каждой, подход — 20 вопросов, сначала ошибки и нерешённые.
   Мини-билет (/mini/5|10|15): N случайных разных вопросов из всей базы
   (/api/random), ответ и пояснение сразу — когда на целый билет нет времени.
Мотивация (app.js, «мотивация»): по ходу — фраза к ответу из набора
(похвала или поддержка), «+1» и значок серии верных подряд на 3/5/10/15/20;
только там, где правильность видна (на экзамене — нет). В конце билета и
экзамена — карточка поверх экрана: финишный флаг, огонёк, конфетти в цветах
дорожных знаков, машина подпрыгивает, дорога разгоняется; заголовок —
случайный из набора (идеально / сдал / поддержка при провале), подзаголовок —
прогресс («новый рекорд билета», «сдан за 12:40»). Мини-билет, ошибки, темы
празднуют только когда всё верно.

Долгая мотивация (assets/motivation.js — чистые функции от «фактов»; один
файл и в браузере, обычным <script>, и на сервере через require):
   - Факты собирают lib/store.js facts() (в /api/me и в итогах билета и
     экзамена) и progress.js guestFacts() — в одной форме: выученное, ошибки,
     ответы, билеты, экзамены, огонёк, 14 последних дней, лучшая серия
     верных подряд, рекорд дня, «ночной/ранний» ответ.
   - Готовность к экзамену — полоса внизу приборки: 70% — выученные вопросы,
     30% — сколько из последних пяти экзаменов сдано. «Готовы к ГАИ» — 90%
     выучено и три последних экзамена подряд сданы. Под полосой — до двух
     следующих шагов (закрыть ошибки, выучить ещё N, сдать экзамены подряд).
   - Рубежи огонька 3/7/14/30/50/100 дней: большой праздник на рубеже, новый
     огонёк и новинки в гараже (/garazh, noindex). Гараж (motivation.js CAR):
     кузов (7 цветов), полосы, спойлер, подсветка, выхлоп. Открытое — по
     лучшей серии и навсегда; что надеть, человек выбирает сам: цвет кузова
     сам не меняется никогда, а деталь, пока её не трогали, ставится первая
     открытая. Выбор — profiles.car_json (PUT /api/me/car, сервер проверяет,

     (кириллица и латиница), цифры, пробел, дефис; хранится там же (car.plate),
     проверяется motivation.js normalizePlate и на клиенте, и на сервере.
   - Огонёк растёт вместе с серией, как в TikTok: уровень пламени = число
     взятых рубежей (motivation.js flameTier). 3 дня — язычок больше, 7 —
     второй слой внутри того же силуэта и ореол, 14 — раскалённое белое ядро, 30 — синее пламя,
     50 — сияющее синее, 100 — фиолетовое «легендарное». Уровень виден везде,
     где есть огонёк: приборка (с названием уровня), шапка билета, друзья.
   - Неделя — календарная, с понедельника по сегодня, против того же отрезка

     localStorage (отдельно гость и каждый аккаунт) — новый показывается
     тостом один раз. Страница /znachki (noindex): рекорды, все значки с
     прогрессом, таблица тюнинга.

Приложение ставится на экран (PWA): manifest.webmanifest, sw.js в корне,
иконки 192/512 (знак на сине-чёрном, сгенерированы Canvas'ом в браузере).
sw.js кэширует оболочку, картинки и билеты/темы — решать можно без сети;
личное API мимо кэша (ответы без сети и так уходят в outbox).

4. ✅ Друзья, «подтолкнуть», вечернее напоминание.

   Сделано так: /api/friends — список из Auth (токеном пользователя) +
   огонёк, норма сегодня, билеты сдано и последний экзамен каждого друга
   (store.friendsFeed). «Подтолкнуть» / «Позвать» (если друг ещё не
   открывал сервис) — уведомление через Auth /api/notifications от имени
   толкающего, раз в день на пару (таблица nudges), не тому, кто сегодня уже
   решил. Вечернее напоминание — раз в 5 минут store.dueReminders (время по
   поясу адресата, по умолчанию 20:00, настраивается на /plan), отправка
   через Auth /internal/notifications по ADMIN_INTERNAL_KEY — токена
   пользователя в этот момент нет. Входящие толчки и напоминания при
   открытии приложения показываются тостом и гасятся.

   Уведомления на устройство (в трей), даже когда сайт закрыт — Web Push
   без зависимостей (lib/webpush.js: VAPID ES256 + шифрование aes128gcm,
   сверено с эталоном RFC 8291). Подписка — на странице плана («Включить»,
   разрешение спрашиваем только по нажатию), хранится в push_subs; туда же
   идут толчки и вечерние напоминания (напоминания теперь работают и без
   ADMIN_INTERNAL_KEY — тогда только push). iPhone — только после установки
   на экран «Домой» (iOS 16.4+). Подписка своя у pdd, не у Auth: push
   привязан к origin service worker'а, а ставят именно pdd.
